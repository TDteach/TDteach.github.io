<p>实验使用 OLMo-2-1B 和 GSM8K。作者根据观察到的模型失误定义了六种错误类型，将它们注入标准推理轨迹，并在 361 种配置中改变污染比例、错误位置以及轨迹与答案的一致性，污染比例最高达到 100%。基于正则表达式的传播程序会将修改后的数值传递到后续公式和最终答案；它只适用于与这种格式兼容的轨迹，因此跳步或隐含步骤不在测试范围内。随后，每个 SFT 检查点都使用完整且未受污染的 GSM8K 训练集进行 GRPO。主要评估指标是在包含 1,319 个样本的测试集上的 pass@2。</p>
<p>关键结果呈现出不对称性：汇总后的 SFT 单独训练准确率从标准数据基线的 43.61% 降至完全污染时的 13.80%。然而，经过 GRPO 后，在不同污染比例下，汇总准确率与标准 SFT+GRPO 基线的差距均在 0.5 个百分点以内，包括完全污染的情况；这是汇总层面的结果，并不保证每次运行都如此。初始化消融进一步凸显了实际启示：仅用八个错误的三行纯格式样本进行 SFT，经过 GRPO 后可达到 69.30%；而不进行 SFT、直接使用 GRPO 时为 35.00%。另外几种极简纯格式初始化也优于标准推理轨迹初始化；相较于 GRPO 后标准初始化的 60.71%，报告的最高提升分别为 9.11 和 8.59 个百分点。在整个配置网格中，SFT 单独训练的准确率与 GRPO 后准确率之间的相关性接近于零，且统计上不显著（r 从 -0.0631 到 0.0002）。</p>
<p>作者将这些模式解释为：SFT 建立回答形式，而 RL 培养推理功能；但本文并未独立分离验证这一机制。因此，可迁移的实验操作是开展受控预算测试：系统地污染轨迹内容、固定验证器训练数据，并在投入推理依据整理工作之前，比较完整轨迹 SFT 与极小规模的纯结构初始化。</p>
<p>不要将结果推广到测试边界之外：评估只使用了一个基座模型和 GSM8K，作者指出更大的模型和更难的任务尚未测试。六种错误类型覆盖了观察到的数值错误中的 93.51%，而非所有错误。复现实验的关键问题是：当任务、模型、轨迹语法或验证器发生变化时，纯格式热启动是否仍保有优势。</p></div><p class="reading-reason">阅读本文，判断你的下一项后训练实验应将标注预算投入精确推理轨迹，还是先测试一种极简结构热启动，再进行基于验证器的 RL。</p><details class="pn-sources"><summary>来源位置</summary><nav class="sources" aria-label="原文位置"><ul><li><a href="https://arxiv.org/abs/2611.26756v1" rel="noopener noreferrer">abstract; §3.4 Regex-based propagation; §5.1 SFT degrades, but RL corrects; §4.7 Evaluation; §5.5 SFT before GRPO is still needed; §5.3 Form-only initialization outperforms standard initialization; §5.4 SFT accuracy is weakly associated with post-GRPO performance; Table 1; §1 Introduction; Limitations</a><span class="pn-source-id">arxiv:2611.26756v1</span></li></ul></nav></details></article>
<article class="pn-article" id="paper-2611.26803" aria-labelledby="heading-paper-2611.26803"><h2 id="heading-paper-2611.26803">在报告的设置中，已保存的 GRPO rollout 支持分阶段学生蒸馏，无需额外进行教师生成</h2><p class="paper-title"><a href="https://arxiv.org/abs/2611.26803v1" rel="noopener noreferrer">Don&#x27;t Discard Your Rollouts: Reusing Teacher RL Traces for Student Distillation</a></p><div class="pn-prose"><p>经典蒸馏通常会丢弃教师的 RL 轨迹，并根据最终教师模型重新生成数据。这带来了一个具体的基线问题：直接对已保存的 rollout 进行 SFT，表现不如经典蒸馏；直接使用 DPO 则不稳定，在较弱的学生模型上还可能崩溃。实际问题是，能否利用档案中已有的元数据，让轨迹复用更有选择性。</p>
<p>该方法将 rollout 复用视为数据选择问题，并使用 GRPO 已记录的元数据。根据提示词通过率对档案排序：最容易的提示词用于 SFT 热启动，随后使用成功率不一的提示词进行 DPO。对于每个提示词，缓存的教师对数似然被用作代理指标，以筛选与学生模型相适配的补全结果。该方案在数学推理和 Python 编码任务上进行评估，学生模型来自多个模型家族。</p>
<p>最有力的比较结论有明确条件。在报告的数学任务平均指标上，经过筛选的 SFT 到 DPO 轨迹复用比经典合成数据蒸馏低 0.37 个百分点，95% 置信区间为 [-0.82, +0.08]，包含零；这是两位教师、五个学生模型和五个基准测试上的平均结果，并不表示每种设置都达到同等表现。与直接复用相比，这一差异很有说明性：在全部十种数学任务的教师—学生设置，以及八项编码比较中的七项里，随机抽取已保存 rollout 进行 SFT 的表现都逊于经典蒸馏。与随机选择补全结果相比，基于缓存教师似然的筛选在报告的数学 SFT 和 DPO 比较中有所提升。在一个支持数据较少的案例中，SFT 热启动使 Gemma-2-2B 在 MATH500 上的成绩从 4.3% 提升至 17.1%，分别对应独立使用 DPO 和采用热启动后使用 DPO。</p>
<p>对于 GRPO 流程，可迁移的操作是保留提示词通过率和每个补全结果对应的教师似然，然后将 SFT 到 DPO 的分阶段方案与随机选择以及重新生成数据的做法进行比较。表 2 报告称，在所列设置中，该方案新增的补全数量和响应 token 数均为零；但这一统计不包括此前为创建档案而进行的 GRPO 生成。最后，需明确适用边界：测试的教师模型为 4B 和 8B，学生模型为 1.2B–4B，因此能否迁移到更大的容量差距仍是开放问题；报告中的评估重复次数也不能替代多个训练随机种子。</p></div><p class="reading-reason">如果你已经在运行 GRPO，阅读本文可以了解如何具体测试已归档轨迹能否替代单独进行的一轮教师生成。</p><details class="pn-sources"><summary>来源位置</summary><nav class="sources" aria-label="原文位置"><ul><li><a href="https://arxiv.org/abs/2611.26803v1" rel="noopener noreferrer">abstract; Section 7.1, Closing the Gap to Canonical Distillation; Appendix B.1; Section 7.2, The Need for Data Selection; Appendix C.1, Table 12; Section 7.3, When Does Preference Learning Help?; Section 7.1, Table 2; Section 8, Limitations</a><span class="pn-source-id">arxiv:2611.26803v1</span></li></ul></nav></details></article>
<article class="pn-article" id="paper-2611.26863" aria-labelledby="heading-paper-2611.26863"><h2 id="heading-paper-2611.26863">在所测试的 GRPO 设置中，获得奖励的自生成错误事实变得更容易回忆</h2><p class="paper-title"><a href="https://arxiv.org/abs/2611.26863v1" rel="noopener noreferrer">LLMs Memorize Their Own Hallucinations During Post-Training</a></p><div class="pn-prose"><p>这里具体的局限在于测量方式：结果奖励可能因为一次 rollout 得出了正确的最终答案而接受它，却不检查其中间的错误论断。因此，本研究考察的是：在这类轨迹中生成的错误原子事实，之后是否会变得更容易被回忆，而不只是评估最终答案。</p>
<p>作者为知识问答采样 RL rollout，从最终答案正确的 rollout 中提取原子错误论断，将每条论断转成多项选择题，并探测该事实进入训练前后的已保存检查点。他们将记忆定义为事实出现后检查点级回忆率的变化，即比较后续回忆率与相应更新发生前的回忆率。对 HalluSet-train 的主要分析排除了未生成正确 rollout 的问题，因此其主要效应并不代表所有训练问题，也不代表错误答案轨迹。</p>
<p>在两个模型家族、两种架构的六个开放模型上，作者使用 GRPO 对 QuALITY 和 TriviaQA 进行后训练。对于来自训练集中正确答案 rollout 的幻觉事实，回忆率平均上升 4.83 个百分点；而对于来自留出问题的幻觉事实，回忆率上升 0.17 个百分点。这是多项选择题探测所得回忆率的变化，并非对自由形式幻觉概率的直接估计。论文还报告，模型会记住那些在推理过程中立即撤回的错误事实。错误 rollout 的对照组通常没有出现相同的正向记忆模式，不过在所有设置中，其得分并非都不高于零。</p>
<p>作者报告称，来自较难训练问题的幻觉事实记忆得分更高，但这只是依赖图示的定性趋势：所提供的文本未给出图中数值或其变异程度。仅在 QuALITY 上，GRPO 的 KL 系数设为 0.001 时，记忆得分有所降低但并未消失，平均降低 0.52 个百分点；这不能证明 TriviaQA 或其他配置中也会出现相同表现。幻觉提取、标注和多项选择题构造在很大程度上依赖 GPT-4.1-mini；附录报告的精确率为对抽取的 200 条 TriviaQA 标注进行验证所得的 98%，并非对所有设置都做了验证。</p>
<p>可借鉴的操作是在训练期间记录原子事实陈述，将每条陈述关联到它首次出现的检查点，并保留留出数据和错误 rollout 对照组。一个有价值的后续研究方向是测试过程级事实惩罚能否降低错误论断之后的回忆率，同时不降低正确最终答案的比例。</p></div><p class="reading-reason">阅读本文，借鉴其检查点探测设计，再测试其回忆信号在自由形式评估和过程级评估中是否仍然成立。</p><details class="pn-sources"><summary>来源位置</summary><nav class="sources" aria-label="原文位置"><ul><li><a href="https://arxiv.org/abs/2611.26863v1" rel="noopener noreferrer">abstract; §2.2, [S2.SS2.SSS0.Px3.p2-p3]; §2.1, [S2.SS1.SSS0.Px2.p1-p4]; §3, Table 1 ([S3.T1]); §2.2, [S2.SS2.SSS0.Px2.p1-p2]</a><span class="pn-source-id">arxiv:2611.26863v1</span></li></ul></nav></details></article>
<article class="pn-article" id="paper-2611.27068" aria-labelledby="heading-paper-2611.27068"><h2 id="heading-paper-2611.27068">固定决策模型为智能体强化学习提供零样本步骤信用</h2><p class="paper-title"><a href="https://arxiv.org/abs/2611.27068v1" rel="noopener noreferrer">Decision Models Are General-Purpose Process Reward Models</a></p><div class="pn-prose"><p>基于可验证结果的 RL 每个回合只给语言智能体一次奖励，因此每一步都获得相同的信用。如果一组中的每条 rollout 都失败，二元回合结果就无法对这些 rollout 内的步骤进行排序。DM-PRM 针对这一缺口，向一个固定的决策模型询问每一步是否取得进展，将其回答概率转化为标准化信用，并把该信用加到基础策略梯度优势上。这种方法是零样本的：不使用步骤标签、微调或学习得到的评论家模型。</p>
<p>最有用的证据是有条件的，并非普遍成立。在 ALFWorld 训练早期的九组实验中，每组抽取的八条 rollout 均告失败；作者报告称，步骤信号仍能区分有用行动和低效行动。在该分析中，探索或与物体交互的步骤占所有步骤的 21%，但在信用值最高的十分之一中占 93%。这支持了该方法能提供早期训练信号的机制解释，但该分析针对的是经过筛选的全失败组别，并非因果干预。</p>
<p>在报告的基准设置中，将 DM-PRM 加入 GRPO 后，ALFWorld 的六种任务类型、已见和未见任务的汇总结果，以及 WebShop 的得分和成功率均优于论文中的 GRPO 结果。该信号在汇总基准结果上也改善了 GiGPO 和 GraphGPO 的表现，因此论文将其视为能够补充现有步骤级信号的插件，而非替代品。</p>
<p>基线是一个核心设计选择。论文报告称，WebShop 使用汇总基线时，浏览和购买行为都会减少；因此，作者改用按动作类型区分的基线，并通过试运行选择信用权重。新的环境需要设置适合自身的问题文本，也可能需要按动作类型设定基线。因此，可复用的经验是将其作为实验设计问题：固定策略梯度方法，比较汇总标准化与按动作类型标准化，并同时检查行为和任务结果。</p>

<article class="pn-article" id="paper-2611.27227" aria-labelledby="heading-paper-2611.27227"><h2 id="heading-paper-2611.27227">CreditFilter 校准无评论家型 RLVR 的回复内软熵权重</h2><p class="paper-title"><a href="https://arxiv.org/abs/2611.27227v1" rel="noopener noreferrer">CreditFilter: Calibrated Token Weights over the Within-Response Entropy Rank for RLVR</a></p><div class="pn-prose"><p>无评论家型 RLVR 通常会为每个 token 分配相同的优势值。此前的一种做法只保留熵最高的 20% 位置上的策略梯度，但 CreditFilter 提出，采用这种启发式方法并不能衡量某个 token 对结果的实际影响。</p>
<p>CreditFilter 将这一目标形式化为<strong>分叉价值</strong>：在策略下一 token 的各种选择下，成功概率的方差。对于固定提示词的在线策略 rollout，若使用二元验证器，则一条回复中各位置的预期分叉价值之和等于该提示词奖励的方差。这种分解将分叉概率与分叉后果区分开来：前者可由 softmax 得到，后者则需要通过代价高昂的后续采样来估计。</p>
<p>CreditFilter 不为每个训练 token 都估计分叉后果，而是在每条回复内部对熵位置排序，并依据该回复内的排名应用指数窗口。在 Qwen3-8B-Base 上测得的分叉概率曲线近似呈指数下降，正确回复和错误回复的拟合宽度分别为 0.111 和 0.155。CreditFilter 利用这一曲线校准其加权窗口。离线校准后，训练器根据已有的 rollout 和策略量计算权重，因此该规则不需要额外的训练时前向传播。</p>
<p>在三个随机种子下，CreditFilter 在 MATH500、AIME24 和 AIME25 上分别比 DAPO 高 7.7、10.5 和 9.1 个百分点。不过，比较时需要说明预算条件：在相同步数下，由于回复更长，CreditFilter 使用的 token 数是 2.1 倍；而论文中按 token 数相同进行的比较仅使用了一个随机种子。</p>
<p>可借鉴的研究操作是：先推导所需的信用分配预算，再用后续采样校准一个廉价代理指标，随后分别消融排序坐标和衰减率。在本文中，跨批次排序会使成绩下降 5–8 个百分点，将校准后的窗口宽度加倍则会使成绩下降 9–15 个百分点，不过这些消融实验都只运行了一次。该代理指标也有明确边界：测量的是 softmax 分叉概率，而分叉后果仍需付出高昂代价才能估计。训练证据的适用范围较窄：所有结果都使用同一个基座模型和同一组提示词，AIME 测试集每组包含 30 道题，且 token 上限为 20,480。</p>
<p>阅读本文，可以了解如何将基于后续采样的测量转化为一种无需额外前向传播的 RL 规则，同时将校准、计算预算和代理指标有效性分别考量。</p></div><p class="reading-reason">阅读本文，了解如何将基于后续采样的测量转化为一种无需额外前向传播的 RL 规则，同时分别考量校准、计算预算和代理指标有效性。</p><details class="pn-sources"><summary>来源位置</summary><nav class="sources" aria-label="原文位置"><ul><li><a href="https://arxiv.org/abs/2611.27227v1" rel="noopener noreferrer">abstract</a><span class="pn-source-id">arxiv:2611.27227v1</span></li><li><a href="https://arxiv.org/abs/2506.01939v2" rel="noopener noreferrer">Section 5.3, High-entropy tokens drive reinforcement learning for LLM reasoning; Table 2</a><span class="pn-source-id">arxiv:2506.01939v2</span></li></ul></nav></details></article></div>
